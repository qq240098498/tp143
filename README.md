# tp143 联赛赛程与积分核算台

一个本地小工具：把参赛球队、比赛场地与整季赛程登记进来，打完的场次记上比分，页面立刻算出每个积分、净胜球与名次。左侧切视图，右侧抽屉里增删改，所有数字都来自本机的数据文件，不连数据库，也不调用任何外部服务。

## 技术栈

- 后端：Node.js（>=18）与 Express，前后端同一个进程
- 前端：原生 HTML、CSS 与 JavaScript，页面由后端静态目录直接提供，没有构建步骤
- 存储：本地 JSON 文件 `data/db.json`

## 启动方式

```bash
npm install
npm start
```

启动后打开页面地址：<http://localhost:5143>

端口固定为 `5143`，如需临时改动可在启动前设置环境变量 `PORT`。

## 页面怎么用

左侧导航共七个视图：

1. 概览：球队与场地数、赛程进度、已赛与待赛场次，下面列出最近五场赛果与积分榜前三
2. 球队：按参赛状态筛选、按队名或城市搜索；点新增或编辑打开右侧抽屉填写队名、简称、城市、主场、档位、状态与备注
3. 场地：以卡片列出场地名称、城市、容量、可用日、主场球队与已排场次
4. 赛程：按轮次与状态筛选，逐场列出日期、时刻、对阵、比分、场地、裁判组与状态；裁判没派齐的场次整行标黄并显示「缺 N 人」，点它直接跳去派场；未打完的场次可以点登记比分
5. 裁判：名册按在册状态筛选；列出每人本季已派场数与剩余名额；点「已派场次」按人查看清单并在相邻两天连吹处标黄
6. 派场：看板把没派齐的场次排在最前面单独提醒，按轮次筛选；一场派一名主裁与两名助理，候选人在同一天有场、本季已满或已停用时不可选；右上角「改派记录」查看全部留痕
7. 积分榜：按名次列出场次、胜平负、进球失球、净胜与积分

任何一步不成立时，右上角弹出说明，并尽量把问题标到抽屉里对应的输入项上。

## 派场口径

每场比赛要派**一名主裁加两名助理**，三人不能重复；派场守住三条：

- **同一天同一人只能出现在一场里**：硬规则，违反当场拒绝，并说明他当天已经在吹哪一场
- **相邻两天连着吹只提示不拦截**：保存后弹出提醒，派场看板该场日期下标出连场人，按人清单里对应的两场都标黄
- **一人一季派场总数上限七场**：硬规则，再派就超的提交当场拒绝，消息写清已派几场、上限几场、这一场会超几场

其他口径：

- 裁判分国家级、一级、二级与在册、停用；停用的人不出现在候选里，也不能被派场
- 还挂着派场的裁判不能删除，页面说明还挂着几场，先改派或撤场再删
- 某人临时不能来时：在裁判视图点「已派场次」列出他所有场次，逐场点「改派这场」换人；改派后自动回到他剩余的场次清单，方便连续处理
- **改派留痕**：每次派场、改派、撤场都记一条，写清比赛快照（轮次、日期、时刻、对阵）、位置（主裁/助理）、原裁判、新裁判、原因、操作者与时间，裁判或赛程后来删除也不影响历史记录
- 派场位置可以先留空，但**没派齐主裁与两名助理的比赛不能登记比分开赛**，拒绝消息列出还缺哪些位置；已赛场次的裁判组锁定不能再改
- 已经派了裁判的赛程改日期时，如果裁判同一天还有另一场，会被拦下并提示先改派
- 赛程删除时它上面的派场一并清掉，改派留痕作为历史保留

## 积分与排序口径

- 只统计状态为已赛的场次，延期、取消与待赛的场次不计入
- 积分按胜一场 3 分、平一场 1 分、负一场 0 分累加，规则记在数据文件的 `meta.points` 里
- 名次依次比较：积分高的在前 → 净胜球多的在前 → 进球多的在前 → 队名排序
- 净胜球等于进球数减失球数；积分榜随每次登记比分实时重算

## 登记口径

- 球队名称不重复、最长 24 个字；简称是两到四个大写字母且不重复；档位在 1 到 12 之间且不重复；主场必须是已登记的场地；本赛季参赛球队最多 12 支
- 场地名称不重复、最长 30 个字；容量在 100 到 200000 之间；至少要选一个可用日，且同一天不能重复勾选
- 赛程的轮次在 1 到 40 之间，日期要真实存在，开赛时刻写成两位小时加两位分钟；主队与客队不能是同一支
- 同一轮里一支球队只能出场一次；同一天同一块场地两场比赛之间至少隔两小时（场地留空时按主队主场算）
- 比分只在状态为已赛时填写，取值是 0 到 99 的整数；状态不是已赛时填了比分会被拒绝
- 球队或场地被赛程引用时不能直接删除，页面会说明还有多少场挂着
- 裁判姓名不重复、最长 12 个字；级别只能是国家级、一级、二级；停用后不能再派场；还挂着派场时不能删除
- 派场规则见上面的「派场口径」：同日不兼场、相邻两天给提示、一季七场上限；同一场三个位置不能是同一人；没派齐不能开赛

## 数据存储

所有数据写在 `data/db.json`，结构为 `{ meta, teams, venues, matches, referees, assignments, assignmentLogs }`。落盘时先写临时文件再改名替换，写入过程中断不会把数据文件写坏；文件缺失或内容损坏时回落到初始数据。初始数据里八支球队、六个场地（其中三支球队共用中立体育场）、七轮单循环二十八场，前三轮已打完并留档裁判组，第四轮有一场延期且只派了主裁（派不齐的示例），其余待赛；另有十四名在册裁判与空的改派记录。

## 接口一览

| 方法   | 路径                        | 说明                             |
| ------ | --------------------------- | -------------------------------- |
| GET    | /api/health                 | 服务状态检查                     |
| GET    | /api/summary                | 概览数字、最近赛果与积分榜前三   |
| GET    | /api/teams                  | 球队清单，支持状态筛选与关键词   |
| POST   | /api/teams                  | 新增球队                         |
| PATCH  | /api/teams/:id              | 修改球队                         |
| DELETE | /api/teams/:id              | 删除球队                         |
| GET    | /api/venues                 | 场地清单，支持关键词             |
| POST   | /api/venues                 | 新增场地                         |
| PATCH  | /api/venues/:id             | 修改场地                         |
| DELETE | /api/venues/:id             | 删除场地                         |
| GET    | /api/matches                | 赛程清单，支持轮次、状态与关键词 |
| POST   | /api/matches                | 新增赛程                         |
| PATCH  | /api/matches/:id            | 修改赛程                         |
| POST   | /api/matches/:id/result     | 登记比分，登记后自动标成已赛；裁判没派齐会被拒绝 |
| DELETE | /api/matches/:id            | 删除赛程，挂在其上的派场一并清掉               |
| GET    | /api/referees               | 裁判名册，支持在册状态筛选与关键词             |
| POST   | /api/referees               | 新增裁判                                       |
| PATCH  | /api/referees/:id           | 修改裁判（含停用）                             |
| DELETE | /api/referees/:id           | 删除裁判，还挂着派场时拒绝                     |
| GET    | /api/assignments            | 派场看板，未派齐排在最前，支持按轮次筛选       |
| PUT    | /api/matches/:id/assignments | 整场派场：主裁一名、助理两名，空串表示位置留空 |
| POST   | /api/matches/:id/reassign   | 单个位置改派或撤场，写一条留痕                 |
| GET    | /api/referees/:id/schedule  | 按人列出已派场次，标出相邻两天连吹             |
| GET    | /api/assignment-logs        | 派场、改派与撤场的留痕，新的在前               |
| GET    | /api/standings              | 积分表，支持关键词                               |

接口出错时统一返回 `{ "error": { "code": "...", "message": "...", "field": "..." } }`，其中 `field` 用于让页面把问题标到具体的输入项上。
