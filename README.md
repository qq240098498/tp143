# tp143 联赛赛程与积分核算台

一个本地小工具：把参赛球队、比赛场地与整季赛程登记进来，打完的场次记上比分，页面立刻算出每个积分、净胜球与名次；裁判派场也在这里做——给每场比赛配齐一名主裁与两名助理，按人查看已派场次与数量，同日撞场、连着两天、超上限都会当场拦下或提示。左侧切视图，右侧抽屉里增删改，所有数字都来自本机的数据文件，不连数据库，也不调用任何外部服务。

## 技术栈

- 后端：Node.js（>=18）与 Express，前后端同一个进程
- 前端：原生 HTML、CSS 与 JavaScript，页面由后端静态目录直接提供，没有构建步骤
- 存储：本地 JSON 文件 `data/db.json`

## 启动方式

```bash
npm install
npm start
```

启动后打开页面地址：<http://localhost:5143>

端口固定为 `5143`，如需临时改动可在启动前设置环境变量 `PORT`。

## 页面怎么用

左侧导航共七个视图：

1. 概览：球队、场地、裁判数与赛程、派场进度；有没配齐的比赛时顶部黄条提醒，已经到开赛时刻仍缺裁判时红条告警；下面列出最近五场赛果与积分榜前三
2. 球队：按参赛状态筛选、按队名或城市搜索；点新增或编辑打开右侧抽屉填写队名、简称、城市、主场、档位、状态与备注
3. 场地：以卡片列出场地名称、城市、容量、可用日、主场球队与已排场次
4. 裁判：按状态、级别筛选与姓名搜索；逐人列出本季已派场数与个人上限、剩余额度和未吹场次数；点姓名展开该裁判名下每一场（轮次、日期、对阵、槽位、状态），待赛或延期的场次可直接改派；临时不能来就点「停派」，停派时提示名下还有几场没吹
5. 赛程：按轮次与状态筛选，逐场列出日期、时刻、对阵、比分、场地与状态；未打完的场次可以点登记比分，打完的场次会带上比分与胜者
6. 派场：顶部单列「派不满的比赛」，已到开赛时刻的标红顶到最前；下面逐场列出主裁、助理一、助理二与相邻两天提示；点「配齐」一次选三个人，点某个槽位的「改派」只换这一个人；「改派记录」查看全部配齐与改派留痕
7. 积分榜：按名次列出场次、胜平负、进球失球、净胜与积分

任何一步不成立时，右上角弹出说明，并尽量把问题标到抽屉里对应的输入项上。

## 积分与排序口径

- 只统计状态为已赛的场次，延期、取消与待赛的场次不计入
- 积分按胜一场 3 分、平一场 1 分、负一场 0 分累加，规则记在数据文件的 `meta.points` 里
- 名次依次比较：积分高的在前 → 净胜球多的在前 → 进球多的在前 → 队名排序
- 净胜球等于进球数减失球数；积分榜随每次登记比分实时重算

## 登记口径

- 球队名称不重复、最长 24 个字；简称是两到四个大写字母且不重复；档位在 1 到 12 之间且不重复；主场必须是已登记的场地；本赛季参赛球队最多 12 支
- 场地名称不重复、最长 30 个字；容量在 100 到 200000 之间；至少要选一个可用日，且同一天不能重复勾选
- 赛程的轮次在 1 到 40 之间，日期要真实存在，开赛时刻写成两位小时加两位分钟；主队与客队不能是同一支
- 同一轮里一支球队只能出场一次；同一天同一块场地两场比赛之间至少隔两小时（场地留空时按主队主场算）
- 比分只在状态为已赛时填写，取值是 0 到 99 的整数；状态不是已赛时填了比分会被拒绝
- 球队或场地被赛程引用时不能直接删除，页面会说明还有多少场挂着

## 派场口径

每场比赛要配齐三名裁判：一名主裁加两名助理。派场时守住三条：

1. **同一天同一人不能出现在两场里**——无论主裁还是助理，当天已经在另一场出场的人在候选人里直接不可选，接口提交也会以 `REFEREE_SAME_DAY` 拒绝并说明是哪场撞了
2. **相邻两天都有派场要给出提示**——不拦截提交，但配齐或改派的返回与派场清单里都会标出「某人前一天/后一天还有第 N 轮一场，连着吹请注意」；候选人下拉里也会写明
3. **一季派场总数超过个人上限当场拒绝**——每名裁判有个人的季上限（默认 12 场，可在裁判资料里改）；再派一场会超时，错误信息写清已派几场、上限几场、这一场超出几场

另有几条配套口径：

- 同一场的主裁与助理不能是同一人，三个人必须互不相同；主裁槽位只能由「主裁」级裁判担任，主裁级可以下任助理
- 处于「停派」状态的裁判不能接新场；停派时把名下还没吹的场次列出来供逐场改派，复岗后才能再派
- **改派必须写清换成谁与原因**：原场次与新场次都在留痕里，记录比赛、槽位、原裁判、新裁判、原因、操作者与时间，可按比赛或按人查询
- **派不满的比赛单独列出**：派场页顶部固定一张缺口清单，已到开赛时刻却没配齐的标红顶到最前；概览页同步黄条/红条告警
- 没配齐主裁与两名助理的比赛不能登记比分（`OFFICIALS_NOT_READY`），保证不会出现比赛已开赛却没有裁判的状态
- 已赛与取消的场次裁判名单锁定，不能再改派；已排好裁判的场次改期时，若现有裁判在新日期与别的场次撞同一天，会先拦下要求改派
- 裁判名下还有派场记录（含已赛留痕）时不能删除，只能停派；取消的场次不再占用裁判名额，也不计入季派场数

## 数据存储

所有数据写在 `data/db.json`，结构为 `{ meta, teams, venues, matches, referees, appointments, logs }`。落盘时先写临时文件再改名替换，写入过程中断不会把数据文件写坏；文件缺失或内容损坏时回落到初始数据。初始数据里八支球队、六个场地（其中三支球队共用中立体育场）、十二名裁判（四名主裁、八名助理，每人季上限 12 场）、七轮单循环二十八场，前三轮已打完并配齐裁判（同日不撞场、每人三场），第四轮有一场延期。

## 接口一览

| 方法   | 路径                        | 说明                             |
| ------ | --------------------------- | -------------------------------- |
| GET    | /api/health                 | 服务状态检查                     |
| GET    | /api/summary                | 概览数字、派场进度、最近赛果与前三 |
| GET    | /api/teams                  | 球队清单，支持状态筛选与关键词   |
| POST   | /api/teams                  | 新增球队                         |
| PATCH  | /api/teams/:id              | 修改球队                         |
| DELETE | /api/teams/:id              | 删除球队                         |
| GET    | /api/venues                 | 场地清单，支持关键词             |
| POST   | /api/venues                 | 新增场地                         |
| PATCH  | /api/venues/:id             | 修改场地                         |
| DELETE | /api/venues/:id             | 删除场地                         |
| GET    | /api/referees               | 裁判清单（带每人已派场次、数量、待吹清单），支持状态、级别与关键词 |
| POST   | /api/referees               | 新增裁判                         |
| PATCH  | /api/referees/:id           | 修改裁判（含个人季上限）         |
| POST   | /api/referees/:id/status    | 停派/复岗，返回名下待吹场次      |
| DELETE | /api/referees/:id           | 删除裁判（有派场记录时拒绝）     |
| GET    | /api/matches                | 赛程清单，支持轮次、状态与关键词 |
| POST   | /api/matches                | 新增赛程                         |
| PATCH  | /api/matches/:id            | 修改赛程（改期撞裁判同日会拒绝） |
| POST   | /api/matches/:id/result     | 登记比分，未配齐裁判时拒绝       |
| DELETE | /api/matches/:id            | 删除赛程（派场与留痕一并清除）   |
| GET    | /api/appointments           | 逐场派场清单，含缺口与已开赛提醒 |
| GET    | /api/appointments/:id/options | 配齐抽屉候选人，逐人标注不可选原因、额度与相邻天 |
| POST   | /api/appointments/:id       | 一次性配齐三个槽位，返回相邻天提示 |
| POST   | /api/appointments/:id/reassign | 单槽改派，必须带换成谁与原因，留痕 |
| GET    | /api/logs                   | 配齐与改派留痕，支持 matchId / refereeId 过滤 |
| GET    | /api/standings              | 积分表，支持关键词               |

接口出错时统一返回 `{ "error": { "code": "...", "message": "...", "field": "..." } }`，其中 `field` 用于让页面把问题标到具体的输入项上。
